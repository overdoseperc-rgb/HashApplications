# Применение хеш-функций

Консольное приложение по заданию «Безопасное хранение паролей». Для запуска требуется .NET SDK 10: `dotnet run` в папке проекта.

При регистрации программа получает имя и пароль, создает случайную соль длиной 16 байт через `RandomNumberGenerator.Create()`, соединяет байты пароля с солью и вычисляет SHA-256. В словаре хранятся только имя пользователя, соль и хеш. При входе хеш вычисляется повторно с сохраненной солью и сравнивается через `CryptographicOperations.FixedTimeEquals`.

Примеры применения хеш-функций на практике:

1. **Проверка пароля.** Сервер хранит соль и результат хеширования, а при входе проверяет введенный пароль. Для реального сервиса вместо одиночного SHA-256 применяют специальные медленные алгоритмы для паролей, например Argon2id или PBKDF2.
2. **Проверка целостности файла.** Публикуют SHA-256 файла. Получатель вычисляет хеш скачанного файла и сравнивает значения, чтобы обнаружить изменение или повреждение. Для подтверждения автора нужен дополнительно доверенный источник хеша или цифровая подпись.
3. **Поиск в словаре.** Хеш ключа помогает выбрать ячейку таблицы, поэтому поиск в `Dictionary<TKey,TValue>` в среднем занимает O(1). При совпадении хешей ключи сравниваются дополнительно.
4. **Цифровая подпись.** Сначала вычисляют хеш документа, затем подписывают его криптографическим ключом. При проверке изменение документа обнаруживается по несовпадению хеша.

Соль делает одинаковые пароли разных пользователей разными по хешу. Она не является секретом. Данные здесь хранятся только в памяти: после завершения программы учетные записи исчезают.
